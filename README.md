# ГОЛОЦИТ

**Анализ данных цифровой голографической микроскопии.**
Версия 1.1.0.

Читает эксперименты штатного ПО микроскопа HoloMonitor M4 (Hstudio),
находит объекты на картах сдвига фазы, измеряет их и формирует отчёт.
Работает рядом со штатным ПО, ничего в нём не меняет и его запуска
не требует.

> Исследовательское программное обеспечение.
> Не является медицинским изделием.

Начинать с `README_FIRST.txt` внутри архива и
`docs/Windows_Build_Guide_RU.pdf`.

## Данных прибора в репозитории нет

Каталоги `demo_data/`, `recovery/` и `vendor/` не выкладываются: они
содержат материалы Phase Holographic Imaging — карты фазы, базу
эксперимента и ресурсы из их установщика.

Поэтому **после клонирования демонстрационный режим не заработает**:
кнопка «Открыть демонстрационный эксперимент» не найдёт данных.

Чтобы он заработал, положите рядом каталог эксперимента Hstudio:

```
demo_data/M4_demo_8/
├── imagedb.xml
└── Storage/PhaseMatrixStorage/0/0/0/1/*.fmx
```

Подойдёт любой эксперимент M4 в формате `.fmx`. Всё остальное — анализ
своих данных через «Открыть эксперимент Hstudio» — работает сразу.

## Что делает

| Модуль | Что даёт |
|---|---|
| **Сегментация** | Находит и разделяет клетки обученной моделью вместо порога яркости. Слипшиеся клетки разделяются корректно |
| **Морфометрия** | 30 параметров на клетку с той же номенклатурой, что и в штатном ПО прибора |
| **Сухая масса** | Масса клетки в пикограммах — величина, которую прибор физически измеряет, но штатное ПО не вычисляет |
| **Состояние клетки** | Норма / митоз / апоптоз / некроз / дебрис — автоматически, по морфологии |
| **Цитотоксичность** | Кривая «доза — эффект», IC50 с доверительным интервалом, по нескольким показателям сразу |
| **Протокол** | PDF с изображениями, разметкой, таблицами, формулами и разделом об ограничениях |

Интерфейс — локальная веб-страница. Наружу ничего не передаётся,
интернет не нужен, видеокарта не нужна.

## Почему сухая масса — это важно

Микроскоп измеряет сдвиг фазы `φ` света, прошедшего через клетку.
Проинтегрированный по клетке, он прямо пропорционален **сухой массе**:

```
m = λ · s²ₓᵧ · Σφ / α ,     α ≈ 0,18 мкм³/пг
```

Коэффициент `α` (удельный рефрактометрический инкремент) почти одинаков
для белков, нуклеиновых кислот и углеводов — поэтому масса не зависит от
предположения о показателе преломления клетки
(Barer, *Nature* 1952; Zangle & Teitell, *Nature Methods* 2014).

То есть прибор — это **весы для отдельной живой клетки, работающие
непрерывно внутри инкубатора, без красителей**. Штатное ПО считает `Σφ`
(параметр *Phase shift sum*), но не переводит его в пикограммы и не ведёт
во времени. ГОЛОЦИТ это делает.

## Установка

### Рабочая станция заказчика (Windows) — переносимая сборка

Основной способ поставки. Устанавливать нечего: копируете папку и
запускаете. Ни прав администратора, ни интернета, ни предустановленного
Python не требуется — всё входит в поставку.

```
1. Скопировать папку ГОЛОЦИТ-windows на машину
2. Запустить Проверка.bat   -> должно быть «Все проверки пройдены»
3. Запустить ГОЛОЦИТ.bat    -> откроется браузер
```

Подробно — в [УСТАНОВКА-Windows.md](УСТАНОВКА-Windows.md), там же раздел
для службы информационных технологий.

Собрать такую папку (запускается на любой системе, в том числе macOS):

```bash
python3 scripts/build_windows.py
```

Сборщик скачивает встраиваемый Python и колёса под Windows x64, кладёт
рядом код, модели и демонстрационные данные, после чего **сверяет версии
колёс с requirements.txt и с отпечатком среды обучения моделей**. При
расхождении сборка останавливается.

### Среда разработки

Нужен Python 3.11.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python3 scripts/train_models.py    # обучить модели, ~1 мин
```

> **Версии в `requirements.txt` зафиксированы жёстко, и это не придирка.**
> Обученные модели сохраняются средствами joblib, а формат этих файлов
> несовместим между версиями scikit-learn и numpy: собранная под одни
> версии модель под другими не загружается вовсе. Среда обучения и среда
> у заказчика обязаны совпадать. Версии записываются в
> `models/versions.json` и сверяются при каждом запуске.

Проверить работоспособность на любой машине:

```bash
python3 -m holocyt selftest
```

## Формат входных данных

Каталог с файлом `manifest.csv` и изображениями:

```
эксперимент/
├── manifest.csv
└── img/
    ├── c0000.0_f1.tif
    └── …
```

`manifest.csv` — разделитель запятая, кодировка UTF-8:

| колонка | обязательна | смысл |
|---|---|---|
| `file` | да | путь к изображению относительно каталога |
| `group` | да | имя группы: «контроль», «12 мкМ» и т. п. |
| `concentration` | для IC50 | числовая концентрация |
| `replicate` | нет | номер повтора |
| `field` | нет | номер поля внутри лунки |
| `time_h` | нет | время от начала эксперимента, ч |

### Прямой импорт из штатного ПО микроскопа

Каталог эксперимента Hstudio читается без всякой подготовки:

```bash
python3 -c "from holocyt.hstudio import make_manifest; make_manifest('/путь/к/эксперименту')"
python3 -m holocyt analyze /путь/к/эксперименту --pixel-size 0.5
```

Формат `.fmx` (карта фазы) разобран: `uint32` ширина, `uint32` высота,
далее `float32` значения сдвига фазы в долях длины волны — те же
единицы, что приняты в ГОЛОЦИТе. Размер пикселя в файле не хранится,
его нужно задавать ключом `--pixel-size`.

Изображения — TIFF, PNG, NPY или .fmx с картой сдвига фазы. Единицы задаются
ключом `--phase-unit`: `waves` (доли длины волны, как в штатном ПО)
или `rad`.

## Проверка на реальных данных

С дистрибутивной флешки прибора восстановлены два повреждённых архива:

| набор | что там | состояние |
|---|---|---|
| **Example woundhealing** (2017) | 56 карт фазы 1024×1024, база `phidbdata.sdf`, 57 голограмм | читается полностью |
| **MCF-10A time-lapse** (2010) | 100 карт фазы `.bin`, 81 голограмма, паспорт съёмки | **паспорт и голограммы читаются, формат `.bin` не разобран** |

### Калибровка прибора

Файл `DBTransferInfo.xml` из второго набора — единственный найденный
источник калибровки. В самих картах фазы её нет.

```
CameraPixelSize = 6,71875 мкм     Lens = 20      ->  пиксель 0,3359 мкм
LaserWaveLength = 633 нм
RefIndexMedium = 1,34             RefIndexObject = 1,38
```

Эти значения приняты по умолчанию. При 1024 пикселях они дают поле
зрения 344 мкм, что соответствует паспортным данным M4. **Стоит сверить
с конкретным прибором**: камера в разных партиях может отличаться.
Задаётся ключом `--pixel-size`.

### Подгонка генератора под реальные клетки

Первый прогон на реальных снимках показал провал классификатора: треть
здоровой мигрирующей культуры была объявлена некротической. Причину
удалось измерить — синтетические клетки имели слишком гладкий контур
(изрезанность 0,16 против 0,64 у реальных), а «некроз» в обучающих
данных был задан как раз через изрезанность.

Генератор перенастроен по измеренным признакам реальных клеток
(инструмент — `scripts/match_real.py`, мера — статистика
Колмогорова — Смирнова, 0 означает совпадение распределений):

| | средний KS | признаков с KS > 0,4 |
|---|---|---|
| исходный генератор | 0,382 | 8 из 17 |
| итерация 1 | 0,241 | 0 |
| **итерация 2** | **0,178** | **0** |

Что это дало на реальных данных:

| | первый прогон | подгонка по признакам | + осмотр отдельных клеток |
|---|---|---|---|
| клеток вне области обученного | 46–55 % | 21,8 % | **8,1 %** |
| «норма» в здоровой культуре | 15,7 % | 53,6 % | **63,8 %** |
| «некроз» в здоровой культуре | 36,2 % | 7,2 % | **5,7 %** |
| митотический индекс | 0,9 % | 1,8 % | **4,8 %** |

Последний столбец — результат прямого осмотра отдельных клеток в
увеличенном виде. Он выявил, что округлившиеся клетки в генераторе
вдвое мельче настоящих (медиана площади 94 против 189 мкм²), а их доля
завышена втрое (29 % против наблюдаемых 9,2 %). После исправления
митотический индекс 4,8 % — ровно та доля клеточного цикла, которую
занимает деление.

Результат стал биологически непротиворечивым: в опыте по заживлению
раны преобладает норма, гибель — единицы процентов, митозов около двух
процентов, что соответствует доле клеточного цикла, занимаемой делением.

**Правдоподобно — не значит проверено.** Разметки реальных клеток
по-прежнему нет.

Границы установлены прямым осмотром, а не предположением:

* **Округлившаяся клетка отличается от распластанной однозначно** —
  толщина 12–19 мкм против 3–6 мкм. Это измерение, а не впечатление.
* **Митоз от апоптоза по одному кадру не отличить.** Оба начинаются с
  округления и на снимке выглядят одинаково; для того и существуют
  красители. Система делит округлившиеся между этими классами примерно
  поровну, и эта доля остаётся непроверенной.
* **Прослеживание по времени здесь не спасает.** Смещение клетки между
  кадрами 9 мкм при её собственном радиусе 8,6 мкм — интервал съёмки
  около получаса, а митоз длится 30–60 минут. Из десяти отобранных
  по строгим критериям кандидатов на деление убедительны два-три.
  На таймлапсе с интервалом 5–10 минут этот путь бы сработал.

### Отказ от ответа на незнакомых данных

Система определяет, попадает ли клетка в область, на которой модель
обучалась (расстояние Махаланобиса, `holocyt/novelty.py`). Клетки вне
этой области получают метку «не определено». Если таких в группе больше
30 %, **состав популяции не сообщается вовсе**:

```
  ⚠ СОСТАВ ПОПУЛЯЦИИ НЕ ОПРЕДЕЛЁН
    50 % клеток не похожи на обучающие данные. Требуется дообучение
    модели на этой клеточной линии. Счёт клеток, площадь,
    конфлюентность и сухая масса от этого не зависят и приведены
    как обычно.
```

Метод выбран по измерению. Доля отвергнутых на отложенной синтетике и
на реальных снимках (до подгонки генератора):

| детектор | своя синтетика | реальные данные |
|---|---|---|
| изолирующий лес | 2,0 % | 14,0 % — мало |
| **расстояние Махаланобиса** | **2,3 %** | **45,9 %** |
| поквантильная проверка | 5,9 % | 50,2 % |

## Результаты на синтетических данных

> **Раздел для разработчиков.** Цифры ниже получены на синтетическом
> генераторе и характеризуют работу программы на её собственных тестах.
> **В пользовательском интерфейсе и в отчётах они не приводятся** и не
> должны использоваться как подтверждение работы на реальных данных.

Эти цифры получены на синтетических полях, не участвовавших в обучении,
но созданных тем же генератором. Они характеризуют работу программы на
её собственных тестовых данных и **не переносятся на реальные снимки**
без дообучения — см. предыдущий раздел. Сравнение с пороговыми
методами, реализованными в штатном ПО прибора:

| метод | F1 | точность | полнота | IoU |
|---|---|---|---|---|
| порог Оцу | 0,328 | 0,495 | 0,249 | 0,753 |
| порог минимальной ошибки | 0,686 | 0,727 | 0,650 | 0,720 |
| адаптивный гауссов порог | 0,758 | 0,740 | 0,778 | 0,725 |
| **ГОЛОЦИТ** | **0,818** | **0,794** | **0,846** | **0,887** |

Цифры ниже прежних (было 0,95) — и это правильно: после подгонки
генератора под реальные клетки задача стала труднее, контуры сложнее.
Прежние значения характеризовали лёгкую синтетику и вводили в
заблуждение.

Главное — не число найденных клеток, а точность границы: от неё напрямую
зависят все измеряемые величины.

**Ошибка измерения у корректно найденных клеток** (медиана):

| метод | площадь | сухая масса | периметр |
|---|---|---|---|
| порог минимальной ошибки | 28,6 % | 10,5 % | 25,0 % |
| **ГОЛОЦИТ** | **3,1 %** | **0,4 %** | **2,8 %** |

**Классификация состояния клетки:** точность 99,8 % (отложенная выборка,
5 классов сбалансированы).

**Восстановление IC50:** в демонстрационный эксперимент заложено истинное
значение 18,0 мкМ. Система по одним лишь изображениям даёт
**17,45 мкМ**, ДИ 95 % (14,7; 21,1), R² = 0,993.

Воспроизвести:

```bash
python3 scripts/benchmark_segmentation.py -n 8 --morphometry
```

## Дообучение на своих данных

Поставляемые модели обучены на физически обоснованных синтетических
изображениях. Для работы с конкретной клеточной линией их следует
дообучить:

1. Снять 10–20 полей этой линии, сохранить карты фазы.
2. Разметить их — годится штатное ПО прибора: инструменты ручной правки
   (`Add/Remove marker`, `Draw cell`) как раз производят маски, пригодные
   для обучения.
3. Заменить в `scripts/train_models.py` вызов `synth_field` на чтение
   своих пар «изображение — маска» и переобучить.

Разметка, которую оператор правит руками при обычной работе, — это
готовые обучающие данные: качество моделей растёт по мере эксплуатации.

---

### Обломки не считаются мёртвыми клетками

Жизнеспособность считается как доля живых среди **клеток**, а
апоптотические тельца и обломки в знаменатель не входят и отражаются
отдельным показателем. Иначе одна погибшая клетка, распавшаяся на пять
телец, засчитывалась бы пятью смертями, и тем сильнее, чем выше доза.
На дозовой кривой такой учёт давал систематический сдвиг: IC50 выходил
14,2 вместо заложенных 18,0. После исправления — 17,45.

## Ограничения

- Заявленные метрики сегментации и классификации получены **на
  синтетических данных**. Проверка на реальных снимках M4 показала:
  сегментация переносится, классификация состояния — нет.
- Классификатор состояния на новой клеточной линии **сначала откажется
  отвечать**, и это правильное поведение, а не поломка. Чтобы он
  заработал, нужна разметка нескольких сотен клеток этой линии.
- Шкала сухой массы требует поверки по эталону известного объёма —
  например, полистироловым микросферам калиброванного диаметра.
- Клетки, касающиеся края кадра, из статистики исключаются (как и в
  штатном ПО).
- Обрабатываются прикреплённые (адгезивные) культуры. Суспензионные
  клетки требуют отдельной настройки.
- **Исследовательское применение.** Система не является медицинским
  изделием и не предназначена для постановки диагноза.

Методическая рамка расчёта цитотоксичности соответствует логике
ГОСТ ISO 10993-5-2011, но показатель отклика измеряется безмаркерно и не
воспроизводит колориметрические конечные точки стандарта (МТТ, нейтральный
красный). Это дополняющий метод, а не прямая замена.
